# M0 capability probes (2026-09-28)

Six in-game runs of a temporary probe mod (`QmProbe`), each started by a launcher that
deployed the mod, ran the game until a marker line appeared and then restored the game
folder: after every run the sha256 of `mods\mods.ini` equalled the baseline, the `mods\`
listing was unchanged and none of the 17,250 other files in the game folder had changed.
Variants: **cap** (probes 1-6, 12), **gui** (9-11), **badinit** (7), **badmenu** and
**baddp** (8), **fileio** (probes 1-2 again, plus the bisect of a compile failure in cap).
Evidence is cited as `m0 <variant>.0.log:<line>`. Earlier probe rounds are cited by name as
in [the plan](../plan.md). Line numbers of vanilla files are relative to the game's `data\`.

## Decisions required by M0

1. **Deletion method (S9):** `DeleteFileStream`, then `FileAge = -1` to confirm. If the file is still there, overwrite it with the current winner's file. No `CopyFileStream`/`MoveFileStream` into a folder that may not exist; no `RenameFileStream` onto an existing file (probe 1).
2. **Screen mechanism:** (a), runtime-added GUI states, re-added by the hook on every DoCreate when missing (probes 9, 10). The main-menu manager button hook in EventMainMenu runs the runtime-added Show state directly, so the (b) tag forward is not needed.
3. **Second hook:** InitMinimap. It runs through InitMap at first start, independently of DoInitialize (probe 7). OnResize also survives a broken DoInitialize (earlier `r9badinit` log), but DoCreate skips it when `bDbgCamera` is set (`gui\menu.inc\docreate.inc:104,126`).
4. **eventmainmenu.inc / doprogress.inc:** not bricks in the S2 sense (the game starts and the menu is built). They are soft bricks, so they are only written after S7 validation, with the S5 fallback tiers (probe 8).
5. **Interning structure:** an own open-addressing hash table in Integer arrays (polynomial hash over `Ord(SubStr())`, strings compared exactly). Named parsers are unsuitable for code lines because they fold case and trim (probe 4).
6. **Myers D cap and layout:** the trace keeps only round d's d+1 same-parity diagonals, at `T[d*(d+1) div 2 + (k+d) div 2]` (k+d is always even and >= 0). That is (D+1)(D+2)/2 Integers; with the 500,000-Integer budget the **D cap is 998** (999*1000/2 = 499,500). The V row covers k in [-cap-1, cap+1] (offset cap+2); the edit arrays hold cap+1 entries. The algorithm, tie-break and backtrack are those that matched the offline reference exactly in probe 6. That run used a full-row layout ((D+1)^2 slots, cap 706) of the same array size. Beyond the cap: winner-takes-all WARN (S14).
